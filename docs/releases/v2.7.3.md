# codex-usage v2.7.3

修复状态库路径失效、归档或索引延迟引起的 `state_schema` 误报，并让已恢复的发现告警自动消退。

- 状态库路径失效时，在当前 `sessions` 和 `archived_sessions` 中查找同名文件；只有文件头的会话 ID 一致且匹配唯一时才恢复路径和状态库 metadata。兼容搬迁 Codex Home、归档和跨系统复制留下的路径，不修改 Codex 状态库。
- 目录扫描已经补齐的 JSONL 不再被视为 schema 错误。仍不可用的源文件单独显示为“部分会话源文件不可用”，并提示核对 Codex Home 或备份；真正无法读取的状态库仍保留告警和目录回退。
- 同一个发现问题不再按轮询次数累加；仅诊断内容变化时增加次数。成功扫描后自动替换旧版误分类告警、清除已恢复告警，并刷新界面缓存；其他解析和计量告警保持独立。
- 现有用量和去重规则保留，无需为本次更新重建历史。**已删除的源 JSONL 无法由本次更新或重建恢复**；缺失文件时请先核对路径或备份。
- 补齐中英文告警名称。

验证：完整 Go 测试、`go vet`、扫描 / 存储 / API 并发检查，以及 28 项 Dashboard / Demo 浏览器测试通过；新增路径恢复、误匹配防护、告警生命周期和中英文展示回归覆盖。

---

Fix misleading `state_schema` warnings caused by stale rollout paths, archiving, or an index that lags behind session files.

- Recover stale paths from the current session and archive directories only when a unique same-name file has a matching first session-metadata ID. Support moved homes and copied Windows paths without writing to Codex's state database.
- Directory supplementation no longer reports a schema failure. Unavailable sources have a distinct warning with recovery guidance; unreadable state indexes still warn and fall back to directory scanning.
- Repeated unchanged discovery results no longer inflate occurrence counts. Successful scans reconcile legacy and resolved warnings and invalidate dashboard caches, while preserving unrelated accounting warnings.
- Preserve existing usage and deduplication. No historical rebuild is needed for this update. Deleted source JSONL files require recovery from their original location or backups; rebuilding cannot recreate them.
- Add Chinese and English warning labels.

Validation: full Go tests, `go vet`, race checks for scanning/storage/API, and all 28 Dashboard/Demo browser tests passed. Added regression coverage for recovery, ownership checks, warning reconciliation, and localized labels.
